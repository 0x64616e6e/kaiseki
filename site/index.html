What it is

kaiseki is the chef-composed set meal: the same “the chef decides” idea as omakase, served on Debian instead of Arch.

It does not fork Omarchy. It takes Omarchy as released, builds Omarchy's own package recipes into Debian packages, and runs Omarchy's own install scripts. Underneath, small stand-ins answer for the Arch tools those scripts call, so Debian's package manager, kernel and ZFS do the actual work.

Current upstream: Omarchy v4.0.4, on Debian testing.

Installing

Boot the ISO and choose a disk. That is the only decision before the system is running; keyboard, account, host name and time zone are asked afterwards, by Omarchy's own first-boot setup.

The desktop

The same Hyprland session, Quickshell bar, menus, themes and keybindings, started the way Omarchy starts them.

How it stays in step

Upstream's recipes, Debian's packages

Omarchy's Arch recipes run under Debian's own makepkg and come out as .deb files. 24 packages are built this way.

Stand-ins, not patches

pacman, snapper, cryptsetup and a few more are answered by small programs that do the Debian equivalent: apt, ZFS snapshots, ZFS re-keying.

A map with a decision per package

Every package Omarchy asks for is mapped to a Debian package, a recipe, or a reasoned “not on Debian”. The map is checked against the real archive.

Tested from nothing, every time

A new virtual machine goes from empty to a checked desktop in 16 minutes, and the installer is driven end to end by key presses, including a cold boot and an update.

Updates through Omarchy's own command

omarchy-update takes a ZFS snapshot, upgrades through apt from a signed repository, and runs upstream's migrations.

Root on ZFS

Encrypted pool, systemd-boot for everyday starts, and ZFSBootMenu as a second entry for snapshots and recovery.

Where it stands

  • Omarchy's packages, system setup and per-user setup run on Debian testing.
  • Installer: one question, encrypted ZFS, no reboot, Omarchy's first-boot setup, cold boot verified.
  • Updates: snapshot first, then upgrade, verified on an installed system.
  • Not tried on real hardware. Everything above was measured in virtual machines.
  • Whole disk only: no dual boot. No Secure Boot.
  • Two of Omarchy's packages are missing (Pinta and the .NET runtime it needs).
  • Control panels, screen recording, printing and sleep have not been exercised yet.
